# Contracts 1.1.0: spec questions are routed without a verifier

## Why

Gate G-F (user chose (a)): sdlc S10 writes a builder's spec question as a `finding-v1`, but C6 said a finding without `verified_by: reproduced` is never routed, so a question could never reach rspec. 01 C6 now names one exception.

**Request (verbatim, via the Orca coordinator, task W1b):** "Contracts 1.1.0 (gate G-F, user chose (a)). 01-shared-contracts.md C6 in C:/Users/Admin/orca/rebuild-upgrade changed: a finding with source: sdlc-question and class: spec-gap is routed to rspec without a verifier, with verified_by {agent: null, result: "not run: spec question"}; every other finding still needs verified_by.result reproduced."

**Coordinator answers:** Q1 (a): a spec question reports an ambiguity, so `repro` and `observed` may be null for `source: sdlc-question` + `class: spec-gap` only, and a new field `question` (string) is required for that source; every other finding keeps both required. Q2: `source` is a pattern `^[a-z][a-z0-9-]*$`, not an enum.

Spec: [docs/specs/rebuild-upgrade/01-shared-contracts.md](../../specs/rebuild-upgrade/01-shared-contracts.md) §C6.

## Decisions

| Decision | Ruled out | Why |
|---|---|---|
| A spec question is `source: sdlc-question`; it must be `class: spec-gap`, carry `question`, and have `verified_by` exactly `{agent: null, result: "not run: spec question"}` | accepting any class or verifier on that source | C6 defines the exception by that exact shape; anything else from that source would be a finding that skips the verifier |
| `repro`, `observed` null and `verified_by.agent` null are schema-legal, and `check_finding` rejects them on any finding that is not a spec question | a JSON Schema `if/then` | the stdlib validator refuses keywords it does not implement; one rule in `check_finding` is smaller than adding conditionals |
| `question` on another source is ignored, not an error | rejecting it | an additive field; consumers ignore unknown fields (C Versioning) |
| Contracts version 1.1.0 (minor) | 2.0.0 | the change is additive: every 1.0.0 finding that was valid stays valid and routes the same way |

## Acceptance criteria

- **AC-001** Given a finding with `source: sdlc-question`, `class: spec-gap`, a `question`, null `repro` and `observed`, and `verified_by {agent: null, result: "not run: spec question"}`, when `contracts.py finding` checks it, then it reports no error and the finding routes to `rspec`. `[request]`
- **AC-002** Given a finding that is not a spec question (another source, or `sdlc-question` without `question`, with another class or another `verified_by`), when it has a null `repro`, `observed` or `verified_by.agent`, or a result other than `reproduced`, then `check_finding` reports the error and the finding is not routed (route `None`). `[request]`
- **AC-003** Given `contracts/v1/` at 1.1.0, when `contracts.py vendor-check` runs, then every file carries the `contracts-version: 1.1.0` header, MANIFEST matches, the new valid fixture passes and the new invalid one fails. `[request]`

## Must never break

- Every finding that was valid in 1.0.0 is still valid and routes the same way; one without `reproduced` is still never routed.
- `contracts/v1/` stays stdlib only, Python 3.9+, and passes `vendor-check` on a fresh checkout.

## Out of scope

- sdlc's `$S question` writer (sdlc-3, S10) and rspec's `/rspec:amend` reading the finding (rspec-5b).
- Re-vendoring 1.1.0 into rspec, sdlc and bug-hunter.
